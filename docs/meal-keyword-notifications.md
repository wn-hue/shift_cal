# 식단 키워드 알림

- 기본 OFF. 전체 > 식단 키워드 알림에서 키워드(20개, 각 30자 이하)와 식사를 선택하고 저장합니다.
- 1차 기준 한국 시간: 점심 11:30, 저녁 17:00, 야식 00:50. 야식은 전날 게시 식단에 대응합니다. 아침 시작 시간은 확인되지 않아 제외합니다.
- Cloudflare work-routine의 5분 주기 작업은 해당 30분 구간에만 Vercel `today-menu?feature=keywords&action=dispatch`를 호출합니다. 식단이 늦게 게시되면 식사 시작 전까지만 재시도합니다.
- Vercel은 기존 12개 함수 내에서 식단 API를 재사용합니다. APNs 서명은 기존 운영 앱 전용 설정을 사용합니다. 새 MEAL_KEYWORDS_CRON_SECRET은 양 플랫폼의 비밀 설정에만 있습니다.
- 비공개 Blob `meal-keywords/subscriptions.json`: 임의 서명 쿠키 소유자, 키워드, 선택 식사, APNs 토큰/환경, 갱신 시각, 마지막 식사 이벤트와 재시도 임대 정보. 이름·급여·위치는 포함하지 않습니다.
- 항상 모드는 근무에 관계없이 동작합니다(기존 구독의 기본값). 근무 모드에서는 주간에 점심·저녁, 야간에 야식만 발송합니다. 전날부터 91일간의 대상 식사만 비공개로 보관하고, 근무표 변경이나 앱 실행 때 갱신합니다. 항상 모드로 돌아가면 날짜별 정보는 삭제합니다.
- 앱 실행 시 활성 구독을 갱신합니다. 90일 미갱신은 발송 제외, 다음 설정 쓰기에서 정리합니다. OFF는 서버에서 구독을 삭제합니다.
- 조건부 Blob 쓰기와 발송 임대가 중복 작업을 막습니다. APNs 무효 토큰은 삭제하고 일시 오류는 5분 뒤 재시도합니다. 식사 시작 후 지연 알림을 보내지 않습니다.
- 알림을 누르면 해당 날짜의 오늘 메뉴 탭이 열립니다. 운영체제 알림/집중 모드에 따라 실제 표시와 소리는 달라질 수 있습니다.

검증: `node scripts/test-meal-keywords.cjs`, `node scripts/test-meal-worker.cjs`, 기존 주차장 APNs 회귀 검사. 운영 주소에서 임시 테스트 구독 생성→조회→삭제와 인증된 비발송 시간대 dispatch를 확인했습니다. 실제 신규 식단 알림 수신은 사용자 opt-in 이후 확인해야 합니다.
