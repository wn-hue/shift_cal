# 교대근무 알람 · iPhone

iOS 26 이상용 SwiftUI/AlarmKit 앱입니다. 기존 Shift_cal 웹앱은 그대로 사용하고, iPhone 기본 캘린더에 동기화된 본인의 Google `Shift_cal A/B/C조` 캘린더를 이 앱에서 선택합니다. Google OAuth 비밀키를 앱에 넣지 않습니다.

## 기능

- 주간·주특: 근무 시작일 06:30, 야간·야특: 근무 시작일 18:30. 한국 시간 기준.
- 앞으로 30일에 해당하는 근무를 일회성 시스템 알람으로 예약합니다.
- 휴무·연차·무급 휴무·개인 일정은 제외합니다. O.T 해제는 기존 근무 시간에 알람을 울립니다.
- 반차는 기본 제외합니다. 설정을 켜면 기존 주·야 시간에 알람을 울리며 실제 반차 출근 시각을 추정하지 않습니다.
- 같은 근무를 중복 예약하지 않습니다. 근무 변경·삭제 시 기존 알람을 취소하고 새 예약을 반영합니다.
- 앱 실행/복귀, 캘린더 변경 통지, 수동 갱신 시 예약을 갱신합니다. 백그라운드 갱신도 요청합니다.
- 권한 거절, 캘린더 삭제, 예약 한도 등 실패는 앱에 표시하며 성공으로 처리하지 않습니다.
- 자동 알람을 끄면 이 앱의 예약을 취소합니다. 기본 시계나 다른 앱의 알람은 건드리지 않습니다.

## 처음 사용하기

1. 웹앱에서 Google 계정을 연결하고 본인의 조 근무표를 연결합니다. 다음 달/연도 전체도 연결하면 향후 근무가 준비됩니다.
2. iPhone 설정 → 앱 → 캘린더 → 캘린더 계정에 같은 Google 계정을 추가하고 캘린더를 켭니다.
3. 기본 캘린더 앱에 `Shift_cal A/B/C조`가 보이는지 확인합니다. 없다면 https://calendar.google.com/calendar/syncselect 에서 동기화를 켭니다.
4. 설치한 교대근무 알람 앱에서 캘린더 접근을 허용하고 자신의 근무 캘린더 하나를 선택합니다.
5. 자동 알람을 켜고 알람 권한을 허용합니다. 예약 목록과 마지막 날짜를 확인합니다.

예약된 알람은 앱이 종료돼 있어도 시스템이 울립니다. **근무 변경 반영과 30일 이후 예약은 앱 실행 또는 iOS가 허용하는 백그라운드 갱신이 필요합니다.** 백그라운드 실행 시각은 보장되지 않으며, 앱 강제 종료/백그라운드 새로 고침 비활성화 시 실행되지 않을 수 있습니다. 웹앱 또는 Google에서 근무를 변경한 뒤 이 앱을 열고 갱신 완료를 확인하세요. 예약 마지막 날짜 전에 주기적으로 앱을 열어야 합니다. 캘린더의 클라우드 동기화도 지연될 수 있습니다.

기본 시계 앱의 목록에 등록하는 기능이 아니라 AlarmKit의 앱 전용 시스템 알람입니다. 캘린더 전체 접근은 iOS 읽기 API에 필요한 권한이며, 코드에서는 선택한 캘린더만 읽고 일정은 쓰지 않습니다. 일정/계정 정보는 서버로 전송하지 않습니다.

## Mac에서 빌드 및 설치

Xcode 26 이상과 XcodeGen이 필요합니다. 저장소 루트에서:

```sh
brew install xcodegen
cd ios-alarm
xcodegen generate
open ShiftCalAlarms.xcodeproj
```

Xcode의 Signing & Capabilities에서 본인의 Apple 개발팀을 선택하고 Bundle Identifier를 팀에서 사용할 고유 값으로 설정합니다. iPhone을 연결하고 Run을 실행하면 실제 기기에 설치할 수 있습니다. 번들 ID를 바꿔도 BGTaskScheduler 식별자는 Info.plist와 소스 양쪽에서 같은 값을 유지해야 합니다.

다른 사용자 배포는 Apple Developer 계정으로 서명한 뒤 TestFlight/App Store에 올려야 합니다. Safari 홈 화면에 추가한 웹앱에는 이 기능이 생기지 않습니다. 개인 무료 서명은 유효기간이 짧으므로 지속적인 근무 알람 용도로는 TestFlight/정식 배포를 권장합니다. 개발팀/인증서/프로비저닝을 제공하지 않은 저장소에는 설치 가능한 서명 IPA가 포함되지 않습니다.

GitHub Actions의 `iPhone 근무 자동 알람 검사`는 시뮬레이터 단위 테스트와 서명 없이 실기기 대상 컴파일을 실행합니다. 출력 프로젝트/검사 결과는 Actions 아티팩트로 제공합니다. 이것은 설치 가능한 앱 파일이 아닙니다.

## 검증

자동 테스트는 한국 시간, 주간/야간/특근/휴무/연차/반차/O.T 해제, 과거 날짜, 30일 예약 범위, 중복, 근무 변경/삭제, 프로세스 재시작 및 예약 실패 재시도를 확인합니다.

실제 소리·잠금화면·무음/집중 모드·재부팅 후 동작은 **실제 iPhone에서 별도로 검증해야 합니다**. CI에서는 물리적인 알람 소리를 검증하지 않습니다.

실기기 확인 절차:

0. 앱의 `1분 뒤 테스트 알람`을 누른 뒤 화면을 잠그고 실제 소리/해제 버튼을 확인합니다.
1. 접근/알람 권한 거절 후 설정에서 다시 허용했을 때 상태와 목록을 확인합니다.
2. 다음 날 주간 또는 야간을 예약한 뒤 앱을 종료하고 잠금 상태에서 06:30/18:30 알람을 확인합니다.
3. 같은 날짜를 연차/휴무로 변경하고 기본 캘린더 반영 후 앱을 갱신해 알람 제거를 확인합니다.
4. 주간↔야간, 특근 추가, 근무 삭제, 조 캘린더 변경, 자동 알람 끄기를 확인합니다.
5. 다른 시간대로 이동해도 한국 근무일/시간이 유지되는지 확인합니다.

공식 API: https://developer.apple.com/documentation/alarmkit/scheduling-an-alarm-with-alarmkit
